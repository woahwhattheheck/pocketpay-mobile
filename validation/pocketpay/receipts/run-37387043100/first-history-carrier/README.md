# First History launch carrier proposal

This is an unexecuted controller-only proposal for the first independent History case at source 52ce8006a2d091a4c9f29852a1a530750ff9b3cc / tree b7556026e93c5930915d12fdf51d421773c5f61e. It does not qualify a product state, repair source, or modify the fixture. Runtime copy is only baseline_history_carrier.py plus baseline-host-runner.py, after independently cleared baseline host adapter 7a6ac932e4c318f688a0ae9785a7dc367506de8add9970c9eefda6b11379938c (or its separately reviewed deadline-only successor). The runner adds exactly an import and installation following the existing host adapter installation at the original collector composition boundary.

The carrier captures the unchanged original launch function's actual first route: exp://127.0.0.1:8081/--/send/__baseline-native-fixture?case=history. It can deliver that identical URI once only before the first product target, product capture, or input. It requires actual fully closed Expo host UI and unobscured Welcome, same current foreground ExperienceActivity/task/PID, exact executed source/tree, and successfully parsed current native logs. Every historical baseline counter (21) and vault transport counter (12) must be zero, both prefixes present, latest baseline ready and wallet present, and lastLock null. Terminal logs from later independent cases and historical Metro records cannot supply this runtime proof.

Before and after delivery, actual native XML/PNG, activity state, observer history and the AM result are retained. Only Status: ok plus LaunchState: HOT with the same activity/task/PID is accepted. No reset, force-stop, fixture seeding, extra delay, other-case or Retry URI is performed by the carrier. The unchanged original case launch still performs its original cold launch. Recognized carrier transport/XML failures are converted to RuntimeError so ordinary polling cannot swallow them or retry the URI.

The narrowly predicted natural first-mount append is a prefix of memory-history-refresh, history-missing, history-instance-mounted, with exactly one mount/removal and one automatic dummy refresh once mounted. A completed mounted state with refresh0 is rejected. Each appended row must have exactly one canned HEAD reachability read and one dummy root/passphrase read, all other transport and operation fields zero, and lastLock null. No new vault event, rebootstrap, hydration, unmount, repeated refresh/removal, other-component operation or changed history is accepted. This is source-derived, not an observed native first-History sequence. Same foreground identity and a strict post-delivery window below the existing 30-second scheduled poll constrain this allowance; the collector's existing global 600-second deadline is never reset. Missing proof fails the case honestly.

The original run 37387043100 first Metro bootstrap rows (lines 28/29) are pure test inputs: ready, wallet present, all 21+12 counters zero. Source proof copies are byte-bound to git source 52 and immutable e69 fixture bytes; installed React Native renderer excerpts identify the child-before-parent effect ordering. They establish the conditional gate, not routing cause or successful native History coverage. Original missing/hydrated/removal same-instance UI, mount/unmount/counter validation remains unchanged and mandatory after any carrier success.

Validation: `python3 -m unittest -v test_first_history_carrier` in this directory. All tests block actual subprocess execution. Private temporary PNG signature bytes are parser test inputs only and are never retained as native media. Tests cover the actual unchanged original launch function and exact runner installation order, once/HOT preservation, all pre-counter fields, wrong source/tree/route/case, target/action/media disarming, launcher/host rejection, PID/activity changes, history/reset/write rejection, exact bounded append sequence and read counts, and failure/expiry no-resume behavior. No ADB/device/native acceptance is claimed.
